# 问题记录

## MuJoCo viewer 启动后不显示模型

- **现象**：`python -m mujoco.viewer test2.xml` 打开 viewer 但画面空白
- **原因**：MuJoCo 3.13.0 的 viewer CLI 必须用 `--mjcf=` 参数指定文件，直接传文件名会被忽略
- **解决**：
  ```bash
  python -m mujoco.viewer --mjcf=test2.xml
  ```
- **验证**：`python -m mujoco.viewer --helpfull` 查看支持的参数

## test2.py / test_control.py 运行后模型运动过快

- **现象**：打开 viewer 后模型运动速度异常快
- **根源**：Windows 上 `time.sleep()` 实际精度仅 ~15ms，而物理步长 `dt=0.01s`（10ms），直接 `time.sleep(dt - elapsed)` 经常睡不够甚至不睡
- **解决**：忙等待 + sleep 混合方式，sleep 只用于 >2ms 的大段时间，最后用忙等待精准收尾
  ```python
  while time.perf_counter() - step_start < dt:
      remaining = dt - (time.perf_counter() - step_start)
      if remaining > 0.002:              # >2ms: 用 sleep 省 CPU
          time.sleep(remaining * 0.9)    # 留 10% 余量
  ```

# 轮腿平衡闭环：整定与标定

> 对象：`b站_车奉朝_腿仿真/wheel_leg_mujoco`。
> 整个闭环只有两件事必须做对：**力给多大**、**方向对不对**。下面按「位形 → 力 → 数值 → 符号」四步走。

## 0. 控制链

```
状态 x(10 维) ──► LQR  u = -K(x - x_ref) ──┬─► T_w ──► ctrl[4..5]   轮子
                                            └─► T_b ──► Tp          髋关节
腿长 L0 ──► PD ──► F0 ──┐
                        ├─► VMC: τ = Jᵀ[F0, Tp]ᵀ ──► ctrl[0..3]  四个腿电机
              Tp ───────┘
```

- LQR 只输出 4 个力矩；腿长由 PD 单独闭环；两者在 VMC 里合成关节力矩。
- VMC 的分工：`F0` 让前后电机**反号**（纯伸缩），`Tp` 让前后电机**同号**（纯摆动）。调试时可据此判断是哪一路出了问题。

## 1. 位形：从哪儿开始

- 目标位形 `θ=0`、`L0≈0.209 m`，即 LQR 的线性化点。`qpos=0` 是前倾 0.65 rad 的位形，不能直接用。
- 四个电机角（由五连杆正解反推，实测 `L0≈0.2086 / θ≈0`）：
  右腿 `jAB=-0.2888`、`jAG=-1.0382`；左腿 `jIJ=+0.2570`、`jIO=+1.0380`。
- 8 个被动关节必须用高斯-牛顿迭代解闭链（残差 `<1e-9`）。随手给 0 会破坏 `<connect>` 约束初值，起步被约束力弹飞。
- **坑：落地高度**
  - 用 `geom_rbound` 估最低点会算错：那是包围球半径，实测把整机抬高 **14.5 cm**（`qpos[2]=0.2747` 时轮子离地 0.1453）。
  - 正确做法：用 `mj_geomDistance` 求每个几何到地面的真实最短距离，再 `qpos[2] -= gap` → `qpos[2]=0.1547`、`ncon=5`。
  - 这个 bug 会让所有闭环结果失真：前 0.15 s 其实是自由落体。

## 2. 力：腿长 PD 给多大

- 方向：`F0 > 0` = 腿伸长（把机体顶起）。`VMC.py` 里“正=收缩”的旧注释是错的。
- 目标腿长：`L_REF = 初始直立腿长 ≈ 0.2086 m`，启动时由 VMC 预热取平均，不写死 0.21。
- 参数：`KP_L = 800 N/m`、`KD_L = 40 N/(m/s)`。
- 重力前馈：理论值 `14.546×9.81/2 = 71.3 N/腿`，实际只给 **70%（≈50 N）**，其余由 PD 补齐。
- 为什么不能给满：空载静平衡点 `L0_eq = L_REF + F0_FF / KP_L`。给 71 N 时 `0.209 + 71/800 = 0.298 m`，腿会一直伸到极限。**前馈必须和腿实际承担的载荷匹配。**

## 3. 数值：首帧的坑

- 现象：首帧 `F0 = -16626 N`，关节力矩瞬间被钳到 ±20 Nm。
- 原因：`last_L0` 初值为 0，而 `d_L0 = (L0 - last_L0)/dt`，首帧得到 `0.2085/0.0005 ≈ 417 m/s`。
- 修法：① `VMC.py` 的 `first_flag` 块里补 `self.last_L0 = self.L0`；② 主循环前先用初始姿态跑一次 `vmc_calc_pos` 预热（顺带得到 `L_REF`）。

## 4. 符号：唯一需要反复核对的地方

文档定义（`WBR_modeling.html`）：由 `s_b = R_wθ_w + R_lφ + l·sinθ_l` (2.5) 得 **θ_l > 0 = 髋在轮子前方**；`T_b > 0` 使髋前移（equ1 系数恒为负）。

实测依据：

| 实验 | 结果 | 说明 |
|---|---|---|
| 机体绕 +y 转 +0.15 | `euler[1]=+0.15`，机顶朝 +x | `θ_b > 0` = 前倾 |
| 左右腿电机各 +0.03 | 右腿轮 x **+0.0064**、左腿 **−0.0062** | 左右腿物理镜像 |
| 两腿分别给 `Tp=+1` | `theta_vmc` 都 **−0.106 rad** | `Tp > 0` 使 theta_vmc 减小 |
| `ctrl[4]=+1` / `ctrl[5]=+1` | qvel **+56.2 / −56.6**，都滚向 +x | 轮 ctrl 正 = 前进 |

由上面四条推出代码里仅有的四处换算：

```python
# ① 状态：把 VMC 的 theta 换算成文档 θ_l（左右腿镜像）
state[4] = -vmc_l.theta;   state[6] = +vmc_r.theta

# ② 髋力矩：让同号 T_b 在两条腿上都表示"髋前移"
vmc_l.Tp =  u[2];          vmc_r.Tp = -u[3]

# ③ 轮力矩：u 的顺序 [左,右] → ctrl[4]=右、ctrl[5]=左
wheel_torque = [u[1], u[0]]

# ④ 左腿关节重排：φ1 接左后 jIO、φ4 接左前 jIJ
joint_torque = [vmc_r.ts[1], vmc_r.ts[0], vmc_l.ts[0], vmc_l.ts[1]]
```

**唯一守则**：状态和力矩必须用同一套符号。只翻一边，髋力矩就会和俯仰反馈互相打架。

## 5. 信号定义

```
x = [s, dot_s, phi, dot_phi, θ_l_l, dθ_l_l, θ_l_r, dθ_l_r, θ_b, dθ_b]
u = [T_w_l, T_w_r, T_b_l, T_b_r]
```

- `s = qpos[0]`、`dot_s = qvel[0]`。不要用 `environment.py` 的 `d_x` 积分，轮径换算有误差。
- `θ_b = euler[1]`、`dθ_b = gyro[1]`。
- `x_ref` 未显式给出时为全零（竖直、静止、偏航 0）；`u = -K(x - x_ref)` 与文档 (3.1) 等价，**不反**。
- 探针读关节角要用 `robot.joint_pos`（`environment.py` 已加标定偏移 `+0.027 / +1.3 / +0.003 / −1.3`），不是原始 `qpos`。
